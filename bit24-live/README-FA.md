# BIT24 AI TRADER PRO — کنسول مستقل دادهٔ واقعی 0.1

## وضعیت تحویل، بدون ابهام

این **نسخهٔ اولیهٔ پنل حساب** است، نه ربات معامله‌گر واقعیِ کامل یا production-certified. هیچ دمو، موجودی اولیهٔ ساختگی، سیگنال جعلی یا سفارش فرضی در برنامه نیست. درخواست شما برای معاملهٔ خودکار واقعی **هنوز تکمیل نشده است**.

پیاده شده: رابط فارسی RTL/انگلیسی، ورود مالک، PWA، backend مستقل بدون وابستگی npm، خواندن احراز هویت‌شدهٔ ارزش کیف پول اصلی، بازارهای IRT و سفارش‌های حساب از مسیرهای مستند رسمی. نبود کلید/قطع شبکه/پاسخ نامعتبر = اعداد خالی و وضعیت «متصل نیست»؛ نه موجودی صفر ساختگی. ورود به پنل به معنی اتصال صرافی نیست.

**آزمون احراز هویت‌شده با حساب واقعی انجام نشده است.** محیط توسعه به میزبان API دسترسی شبکهٔ مجاز ندارد و هیچ کلیدی برای حساب استفاده نشده است. سازگاری با مستندات، اثبات موفقیت اتصال واقعی نیست. اطلاعات حساس را در چت ارسال نکنید.

### موارد تکمیل‌نشده

- تأیید قابل‌اتکای مجوز فقط Spot بدون برداشت/انتقال؛ خواندن موفق موجودی اثبات این مجوزها نیست.
- adapter ثبت و لغو سفارش واقعی، قواعد دقیق امضای سفارش، گام قیمت/حجم و کارمزد واقعی حساب.
- ثبت durable پیش از ارسال، کنترل سقف سرمایه به همراه سفارش‌های رزروشده، تطبیق fills و بهای تمام‌شده، بازیابی پس از restart.
- موتور خودکار، اندیکاتورها، SL/TP/trailing، توقف روزانه و Panic واقعی متصل به صرافی.
- سرور دائمی، HTTPS و تست پذیرش واقعی با اجازهٔ مالک و ممیزی امنیتی مستقل.

**کلید خرید یا Panic نمایشی نداریم.** همهٔ درخواست‌های نوشتن، حتی بعد از ورود مالک، با 423 رد می‌شوند و `orderSubmitted:false` برمی‌گردانند. واردکردن API key هیچ معامله‌ای را فعال نمی‌کند. Secret در این نسخه مصرف نمی‌شود؛ آن را وارد نکنید.

## اجرای روی کامپیوتر / سرور

Node.js 22.12+ یا 24 LTS لازم است. وابستگی runtime خارجی ندارد؛ npm install لازم نیست.

```sh
cd bit24-live
npm run setup
```

این فرمان `.env` خصوصی با مجوز 0600 می‌سازد و رمز قوی OWNER_PASSWORD تولید می‌کند. رمز فقط در همان فایل محلی است و در log چاپ نمی‌شود. فایل موجود را بازنویسی نمی‌کند.

`.env` را فقط روی سرور، در ویرایشگر خصوصی باز کنید:

- `OWNER_PASSWORD`: رمز ورود به همین پنل، نه رمز یا کلید صرافی.
- `BIT24_API_KEY`: در این مرحله فقط کلید محدود برای خواندن؛ اگر مجوز امن قابل تأیید نیست، تنظیم نکنید.
- `BIT24_SECRET_KEY`: برای مرحلهٔ آینده رزرو شده؛ خالی بماند.
- `PUBLIC_ORIGIN`: در اجرای محلی `http://localhost:3050`؛ در استقرار دقیقاً آدرس HTTPS خودتان، بدون مسیر یا اسلش آخر.

```sh
npm start
```

در مرورگر همان دستگاه `http://localhost:3050` را باز کنید و با **OWNER_PASSWORD** وارد شوید؛ فرم مرورگر محل API key نیست. بدون API key همچنان می‌توانید چیدمان پنل و وضعیت قطع اتصال را ببینید، اما هیچ موجودی یا سفارش ساخته نمی‌شود.

برای سرور عمومی، پشت reverse proxy با HTTPS اجرا کنید. Host و Origin باید دقیقاً با PUBLIC_ORIGIN برابر باشند. Caddyfile.example یک نمونهٔ پیکربندی است، نه دامنه یا سرویس فعال. برنامه مسیر API سفارشی/صرافی دلخواه نمی‌پذیرد. از سرور ناشناسِ فروشندهٔ VPN برای کلید صرافی استفاده نکنید. VPN اشتراکی محل نصب backend نیست.

### اجرای موقت فقط روی گوشی

Termux باید از منبع معتبر نصب شده باشد و Node مناسب داشته باشد. پوشهٔ برنامه و `.env` را در فضای خصوصی Termux نگه دارید، **نه Downloads یا حافظهٔ اشتراکی**. سپس فرمان‌های بالا را داخل Termux، نه جست‌وجوی Google، اجرا کنید و در Chrome همان گوشی localhost را باز کنید. در این مرحله کلید واقعی اضافه نکنید؛ ابتدا استقرار و مجوزها را بررسی کنید.

این روش برای مشاهدهٔ پنل است؛ پایداری شبانه‌روزی، اتصال IP ثابت یا معاملهٔ پس‌زمینه تضمین نمی‌کند. Android ممکن است فرآیند را ببندد. برنامه درون اپ رسمی Bit24 نصب نمی‌شود.

### نصب PWA روی Android

بعد از اجرای واقعی backend، در Chrome روی HTTPS یا localhost باز کنید و منوی سه‌نقطه ← Install app / افزودن به صفحهٔ اصلی را بزنید. آیکون، manifest و service worker داخل پروژه‌اند. دادهٔ حساب، cookie، رمز و پاسخ‌های API هرگز در service worker cache نمی‌شوند. حالت آفلاین فقط پوستهٔ خالی است.

نصب PWA به معنی ساخت سرور، مجوز معامله یا اتصال دائمی نیست. APK ساخته نشده و لینک عمومی فعال جزو این تحویل نیست. ZIP برای اجرای مستقیم با ضربه در مرورگر نیست؛ سورس اجراییِ frontend/backend است.

## معنی دقیق اعداد

- ارزش کل و آزاد از `assets.user` خوانده می‌شود؛ دارایی margin، investment و ربات‌های خود صرافی با سرمایهٔ این نرم‌افزار مخلوط نمی‌شوند.
- «ارزش دارایی‌های آزاد به تومان» **موجودی نقد IRT قابل خرج نیست**؛ تبدیل ارزش سایر ارزها به تومان هم در آن وجود دارد. این عدد برای تعیین بودجهٔ سفارش استفاده نشده است.
- قیمت بازار، آخرین مقدار دریافت‌شده است، نه bid/ask اجرایی یا تضمین قیمت.
- سفارش‌های حساب الزاماً توسط این نرم‌افزار ثبت نشده‌اند. سفارش جزئی برابر معاملهٔ بسته نیست. کارمزد با ارز نامعلوم به سود خالص تبدیل نمی‌شود.
- سود و نرخ برد تا وجود دفتر fills و بهای تمام‌شدهٔ تأییدشده `—` هستند. از ظاهر مثبت سفارش، آمار سود اختراع نمی‌شود.
- یک میلیون تومان سقف درخواستی سرمایه و صد هزار تومان سقف بودجهٔ سفارش هستند، **نه موجودی واقعی**. اعمال این سقف‌ها در موتور سفارش هنوز پیاده نشده و پنل همین موضوع را ذکر می‌کند.

## امنیت و خطا

ورود مالک با رمز تصادفی، session در cookie با HttpOnly/SameSite=Strict و Secure روی HTTPS، عمر ۸ ساعت و خروج قابل ابطال است. sessionها حافظه‌ای‌اند و restart آن‌ها را باطل می‌کند. Origin و Host دقیق بررسی می‌شوند؛ ورود محدودیت ۵ تلاش در دقیقه دارد. رمز یا کلید در localStorage/sessionStorage ذخیره نمی‌شود. پیام خام خطای صرافی به مرورگر یا log فرستاده نمی‌شود.

کلید API فقط backend-side از محیط اجرا/secret manager می‌آید. `.env` رمزنگاری‌شده نیست؛ محدودیت فایل به تنهایی جای secret manager، رمزنگاری دیسک، مدیریت بکاپ و ممیزی میزبان را نمی‌گیرد. در تولید از secret manager میزبان استفاده کنید. این نسخه ادعای encrypted-vault integration ندارد.

خواندن‌ها GET-only و محدود به سه مسیر ثابت‌اند. HTTPS، عدم دنبال‌کردن redirect، سقف بدنه ۲MB، timeout سخت ۸ثانیه برای هر درخواست و بودجهٔ ۲۰ثانیه برای کل snapshot شامل خواندن پاسخ، رعایت Retry-After و یکپارچه‌کردن syncهای همزمان پیاده شده‌اند. sync حداکثر هر ۱۵ ثانیه، client هر ۲۰ ثانیه و سن داده از شروع خواندن محاسبه می‌شود و داده با عمر بالای ۳۰ ثانیه مخفی می‌شود. پس از خطای دریافت، snapshot قبلی پاک می‌شود. cache میان کاربران متفاوت وجود ندارد؛ این سرور برای یک مالک است.

صفحه‌بندی تا ۲۰ صفحه در هر endpoint خوانده می‌شود؛ اگر کامل نشود، snapshot رد می‌شود، نه اینکه شمارش ناقص به‌عنوان کل تاریخچه نشان داده شود. تغییر همزمان تاریخچه ممکن است ناسازگاری صفحه‌بندی ایجاد کند؛ شناسهٔ تکراری رد می‌شود اما snapshot صرافی اتمیک نیست. برای معاملات واقعی به reconciliation مستقل نیاز است.

## تست‌ها

```sh
npm test
```

۲۳ تست واحد/HTTP با fixtureهای صریح داخل test، شامل احراز مالک، CSRF، Host، انقضا/خروج، timeout، rate limit، پاسخ نامعتبر، نبود کلید، صفحه‌بندی، قفل نوشتن و پاک‌شدن دادهٔ قدیمی. **fixtureهای تست در runtime وارد نمی‌شوند.**

۱۰ بررسی مرورگر در `reports/browser.json`: RTL/LTR، عرض ۳۲۰/۳۹۳/۱۴۴۰، نبود موجودی ساختگی، خروج، cache نکردن حساب و حالت آفلاین. تصویر `reports/mobile-disconnected.png` پنل بدون کلید است. آزمون روی دستگاه فیزیکی Android، معاملهٔ واقعی، load test یا ممیزی نفوذ انجام نشده است.

اسکریپت توسعهٔ `test/browser.mjs` برای اجرای دوباره به dev dependencyهای مخزن والد (@playwright/test و @sparticuz/chromium) نیاز دارد؛ runtime و `npm test` مستقل‌اند.

## مستند رسمی بررسی‌شده

https://docs.bit24.cash/

- احراز GET: هدر `X-BIT24-APIKEY`؛ نیازی به secret برای این سه خواندن طبق مستند نیست.
- `GET https://rest.bit24.cash/asset/capi/v1/wallet/assets/total`
- `GET https://rest.bit24.cash/pro/capi/v2/markets?quote_coin_symbol=IRT&page=1&per_page=40`
- `GET https://rest.bit24.cash/pro/capi/v2/spot-orders?page=1&per_page=40`

این فایل‌ها adapter **خواندن** هستند؛ هیچ endpoint نوشتن یا روش امضای حدسی در آن‌ها وجود ندارد. قبل از استفادهٔ واقعی، تغییرات مستندات و دسترسی read-only حساب باید دوباره بررسی شوند.
